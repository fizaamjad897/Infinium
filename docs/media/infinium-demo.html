Query targets a change in authentication strategy → causal + temporal.
Anchor: a3f19c2 touches auth/github_oauth.py, adds token exchange.
Prior state: jwt_handler.py issues HS256 tokens with no repository scope.
Constraint in PR #412: private-repo ingestion needs the user's GitHub token.
Conclusion: OAuth layered ahead of JWT, not a replacement.
03Synthesizeminimax-m2.7 · 1.62s
The change came from PR #412, merged three weeks after the JWT-only flow shipped. The commit message on a3f19c2 is explicit: repository access had to be validated against GitHub itself, and a self-issued JWT could not prove the user had read access to a private repo. So OAuth was added in front of JWT rather than replacing it — github_oauth.py exchanges the code for a GitHub token, and jwt_handler.py still issues the session token afterwards. The stored GitHub token is what ingest_repository() later uses for private clones.
